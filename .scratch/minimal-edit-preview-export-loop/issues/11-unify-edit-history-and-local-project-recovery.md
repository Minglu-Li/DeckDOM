# 11 — 统一全部修改的编辑历史与本地项目恢复

**What to build:** 用户对文字、图片、视觉变换和外观做出的所有首版修改共享一套可预测的用户意图级编辑历史，并在浏览器刷新或重新打开后恢复最近项目；保存失败时产品明确告知，避免用户误以为工作已经安全保存。

**Blocked by:** 05 — 就地编辑文字并保留内联结构; 06 — 本地替换图片并在导出时内嵌; 07 — 视觉移动与等比缩放对象; 08 — 应用对象级局部外观覆盖.

**Status:** resolved

- [x] 文字内容、字体属性、图片替换、视觉位移、视觉缩放和外观覆盖全部进入同一编辑历史。
- [x] 历史按用户意图而非指针移动或输入事件数量分组，一次完整拖动、缩放或文字提交只需撤销一次。
- [x] `Ctrl+Z` 撤销，`Ctrl+Y` 和 `Ctrl+Shift+Z` 重做；连续多步操作按照真实提交顺序往返。
- [x] 撤销后产生新修改时，已失效的重做分支不再错误应用。
- [x] 撤销和重做同步更新工作副本、当前选框、HTML 层级状态和对象属性区。
- [x] 用户可以连续撤销回刚导入时的原始效果，而原始上传 HTML 始终保持不可变。

- [x] 本地保存失败、浏览器空间不足或项目数据无法恢复时显示明确且可操作的错误，不继续显示虚假的已保存状态。
- [x] 自动化测试隔离各用例的浏览器存储，并覆盖跨不同操作类型的连续撤销、重做和刷新恢复。

## Answer

审计并统一了文字内容、字体、图片替换、视觉位移、视觉缩放与外观覆盖的现有修改层历史入口。每次明确提交或完整 pointer 手势形成一个历史步骤；三种撤销/重做快捷键现在同时覆盖编辑工作台与工作副本。连续跨类型操作按真实顺序往返，撤销后产生新提交会截断失效 redo 分支；历史应用后重新绑定稳定 ID 对象，使工作副本、选框、层级树与属性面板保持一致，并能连续回到原始导入效果。

每次历史提交都会保存不可变原始 HTML、当前修改层与完整历史。刷新及同一浏览器 context 中重新打开新页面均可恢复最近项目。保存 API 现在返回真实结果：配额不足和其他写入异常会明确标记“修改尚未保存”，提示立即导出 HTML，且不会再被虚假的“已保存”状态覆盖。损坏或结构无效的本地项目会显示恢复诊断，允许用户清除损坏数据后重新选择 HTML。

验证：测试服务器使用 ticket 专用端口 4411；新增真实 Chrome E2E 覆盖六类跨类型历史、快捷键、redo 分支、新页面恢复、配额/一般写入异常及损坏项目恢复；`npm run build`、全套 E2E 与 `git diff --check` 均通过。
