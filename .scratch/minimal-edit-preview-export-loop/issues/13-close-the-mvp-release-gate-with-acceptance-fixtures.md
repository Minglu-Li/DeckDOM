# 13 — 用两份验收样例关闭 MVP 发布门槛

**What to build:** 使用现有翻页式和长滚动响应式验收样例，证明 MVP 已形成稳定的“导入—层级选择—直接编辑—撤销/重做—预览—本地恢复—导出”闭环，并为关键页面状态建立可持续的视觉与交互回归门槛。

**Blocked by:** 04 — 支持参考视口与长页面浏览; 09 — 隔离编辑操作并恢复预览行为; 11 — 统一全部修改的编辑历史与本地项目恢复; 12 — 固化高保真的 HTML 交付文件.

**Status:** resolved

- [x] 两份验收样例均从未经预处理的原始 HTML 输入走完整端到端流程，不依赖测试专用标记或手工改造。
- [x] 两份样例导入后保留主要布局、视觉内容和原文档形态，并能选择常见文字、图片、普通容器与父容器。
- [x] 两份样例均验证文字编辑、图片替换、视觉位移、视觉缩放、字体和对象级外观修改的即时渲染。`test1.html` 的源文件不含 `img`，因此图片替换为 source-fixture N/A；图片路径由未改造的 `test2.html` 完整验证。
- [x] 两份样例均验证跨修改类型的撤销、重做、刷新恢复和最近项目恢复。
- [x] 翻页样例验证编辑模式不会误触上一页、下一页、主题或页面快捷键，预览与导出后恢复原翻页和主题行为。
- [x] 长滚动样例验证编辑模式可滚动到不同区块、参考视口触发原响应式规则，预览与导出后恢复导航和锚点行为。
- [x] 两份样例导出的单文件 HTML 均能在不加载 Web 编辑器的独立页面环境打开并保留全部首版修改。
- [x] 关键初始、编辑后、预览和导出状态具有区域级或页面级视觉回归基线，容差固定并允许可解释的浏览器字体渲染差异。
- [x] 回归检查确认编辑器未引入结构重排、动画删除、原交互失效、未编辑对象样式变化或编辑辅助界面泄漏。
- [x] 所有验收通过才视为 MVP 发布门槛关闭；结果不得被表述为支持所有 AI 生成 HTML。

## Answer

新增 `acceptance-mvp.spec.js`，让未经预处理且 bytes 保持不变的 `test1.html` 与 `test2.html` 分别走独立的导入、层级选择、全部适用编辑能力、跨类型历史分支、本地恢复、预览和 HTML 下载闭环。下载内容由真实浏览器下载后在独立 `file://` 页面打开验证，没有重新调用导出实现。两条场景还固定了初始、编辑后、预览、交付物共 8 张区域视觉基线（关闭动画、外部图片遮罩、`maxDiffPixelRatio: 0.01`），并以未编辑邻居、原结构/动画、原交互和无编辑辅助标记作为负证据。

`test1.html` 源文件没有图片对象，所以其图片替换验收明确记为 source-fixture N/A，未为满足测试而改造样例；`test2.html` 覆盖本地图片替换、恢复和内嵌交付。`release-boundaries.spec.js` 与 README/UI 同步声明：只证明两份参考文件，不代表所有 AI HTML；本地处理不等于完全离线，外链会保留；自动门槛运行最新版桌面 Chrome，Edge 承诺的证据边界另行说明。

目标 acceptance 与 release-boundaries 场景通过；生产构建通过，真实桌面 Chrome 全套 E2E 43/43 通过，MVP 发布门槛据此关闭。该结论仅适用于文档中声明的首版范围与两份验收样例，不扩展为支持所有 AI 生成 HTML。
