# 06 — 本地替换图片并在导出时内嵌

**What to build:** 用户可以确认当前选中的普通图片，从本地选择新图片进行替换，立即按照原对象规则看到真实结果，并让替换在撤销、重做、本地恢复和单文件 HTML 交付文件中保持一致。

**Blocked by:** 03 — 发现并层级选择可编辑对象.

**Status:** resolved

- [x] 对象属性区仅在普通图片对象被选择时提供本地图片替换操作，并显示足以确认目标的图片信息。
- [x] 选择本地图片后，工作副本立即显示替换结果，并沿用原图片对象的布局尺寸和首版基础外观规则。
- [x] 替换只作用于当前选中图片，不改变共享相同类名或来源地址的其他图片。
- [x] 一次替换形成一个用户意图级历史步骤，撤销恢复原图，重做恢复替换图。
- [x] 替换图片数据保存在浏览器本地项目中，刷新恢复不依赖用户再次选择本地文件。
- [x] HTML 交付文件内嵌替换图片，在离开 Web 编辑器且无法访问原本地图片路径时仍能显示。
- [x] 图片选择取消、无法读取和不受支持图片数据会给出明确错误，并保持修改前状态。
- [x] 端到端测试验证即时显示、局部作用、撤销、重做、刷新恢复和独立导出显示。

## Answer

已为普通图片对象增加目标确认与本地替换属性区。替换文件在浏览器中读取并验证为可渲染图片后，以 data URL 写入修改层，立即应用到当前 Editor ID 对应的工作副本对象；原布局与基础外观继续由原对象规则控制。替换复用统一的用户意图级历史、本地项目保存和导出写回路径，因此支持撤销、重做、刷新恢复，并在单文件 HTML 交付文件中内嵌显示。

新增端到端覆盖目标信息、即时真实渲染、共享类名与来源的局部作用、尺寸规则保持、撤销/重做、localStorage 恢复、独立导出，以及取消和无效图片数据保持原状态。验证通过：`npm run build`，`npm run test:e2e`（15 passed）。测试服务器端口使用 4406。
