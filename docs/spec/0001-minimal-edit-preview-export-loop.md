# HTML Visual Editor MVP：最小编辑、预览与导出闭环

## Problem Statement

没有编程经验的用户已经能够借助外部 AI 工具生成 HTML 展示文档，但在内容需要微调时，仍不得不回到提示词反复生成、直接修改 HTML/CSS/JavaScript，或请开发者代为处理。现有演示文稿工具又会把网页转换为固定页面模型，难以保留原文档的布局、滚动形态、动画、脚本与交互。

用户需要一个免登录、低学习成本的 Web 编辑器：它应当直接运行用户已有的单个 HTML 展示文档，让用户像使用演示文稿软件一样选择和修改常见内容，同时优先保持原页面效果。完成修改后，用户需要得到一个脱离编辑器仍可运行的单文件 HTML，而不是项目源码、在线分享链接或必须依赖产品服务的专有格式。

由于任意 AI 生成的 HTML 结构、样式与脚本差异很大，MVP 不能承诺所有内容都完全可编辑。产品必须在“可编辑性”与“导入保真”冲突时优先保留原效果，对无法可靠处理的内容明确锁定，并确保可视化修改不会悄悄改写原始上传文件。

## Solution

提供一个面向最新版桌面 Chrome 和 Edge 的、本地优先且无需登录的 Web 编辑器。用户上传自己信任的单个 `.html` 文件后，编辑器在隔离于编辑器界面布局的运行区域中原生加载它，并以原始 HTML 和独立修改层共同形成实时工作副本。

在编辑模式中，用户可按 HTML 原有层级选择文字对象、图片和普通容器，对文字、图片、视觉位置、视觉尺寸及首版外观属性进行直接编辑。所有已提交操作进入统一编辑历史、立即呈现在工作副本中，并自动保存到浏览器本地。预览模式隐藏编辑辅助界面并恢复原页面的点击、键盘、滚动与动画，以同一份工作副本检查最终效果。

导出时，编辑器基于原始 HTML 的副本固化当前修改：适合直接表达的文字、图片和链接内容写回对应对象，视觉修改以局部导出补丁表达，本地替换图片内嵌到文件中。输出为单个 HTML 交付文件，可在不依赖编辑器的情况下打开并呈现修改结果，同时尽量保留原文档结构、样式、脚本、动画与交互。

首版以一份翻页式 HTML 展示文档和一份长滚动响应式 HTML 展示文档作为端到端验收样例，只交付“导入—选择—基础修改—撤销/重做—预览—本地恢复—导出”的最小闭环。

## User Stories

1. 作为没有编程经验的内容创作者，我想上传一个现有 HTML 展示文档，以便不接触源码也能继续修改 AI 生成的内容。
2. 作为内容创作者，我想从本地选择单个 `.html` 文件，以便直接沿用外部 AI 工具的输出。
3. 作为内容创作者，我想在上传前看到“仅应打开受信任输入”的明确提示，以便理解原 HTML 的脚本和网络请求会真实运行。
4. 作为内容创作者，我想让文档和替换资源只在浏览器本地处理，以便产品服务器不接收我的内容。
5. 作为内容创作者，我想在使用产品前无需注册或登录，以便立即开始一次编辑任务。
6. 作为内容创作者，我想在上传非 HTML 文件时得到明确拒绝和原因，以便知道 MVP 支持的输入边界。
7. 作为内容创作者，我想在 HTML 无法载入时看到可理解的错误，而不是进入空白或不可恢复的工作台。
8. 作为内容创作者，我想在相对本地资源缺失时看到明确提示，以便判断哪些图片或样式需要替换。
9. 作为内容创作者，我想让原 HTML 的布局、颜色、字体、滚动形态、动画和交互在导入后尽量保持不变，以便编辑器不会把作品转换成另一种文档。
10. 作为内容创作者，我想让翻页式 HTML 保留原有翻页结构，以便它不会被强制改造成长页面或固定的产品页面模型。
11. 作为内容创作者，我想让长滚动 HTML 保留原有滚动结构，以便它不会被切割成幻灯片。
12. 作为内容创作者，我想让原文档中可可靠定位的内容显示为可编辑对象，以便知道哪些内容可以直接修改。
13. 作为内容创作者，我想让暂时无法可靠修改的复杂内容保持原样运行并明确显示为锁定内容，以便编辑能力不足不会破坏原效果。
14. 作为内容创作者，我想在锁定对象上看到原因或状态提示，以便不会误以为点击失效或导入失败。
15. 作为内容创作者，我想在默认 1440×900 的桌面参考视口中编辑，以便移动和缩放具有稳定坐标基准。
16. 作为内容创作者，我想调整桌面参考视口的宽高并检查页面，以便了解原文档在不同桌面尺寸下的表现。
17. 作为内容创作者，我想在长页面中继续使用滚轮和滚动条，以便浏览并编辑当前视口之外的内容。
18. 作为内容创作者，我想在编辑工作台中同时看到文件与模式工具、HTML 层级、实时工作副本、对象属性和状态信息，以便理解当前文档、选择与操作状态。
19. 作为内容创作者，我想在编辑模式中单击可见内容来选择对象，以便像使用演示文稿工具一样开始操作。
20. 作为内容创作者，我想让第一次单击优先选中点击位置最小的可编辑对象，以便快速修改具体文字或图片。
21. 作为内容创作者，我想从当前对象沿原 HTML 层级向上选择父容器，以便把一个区块作为整体操作。
22. 作为内容创作者，我想在层级树中定位并选择可编辑对象，以便在重叠、遮挡或难以精确点击时仍能选中目标。
23. 作为内容创作者，我想搜索 HTML 层级树，以便在内容较多的文档中快速找到目标。
24. 作为内容创作者，我想看到当前对象的层级路径，以便理解自己选中的是文字、图片还是外层容器。
25. 作为内容创作者，我想让选框和操作手柄准确跟随当前对象，以便移动或缩放前确认作用目标。
26. 作为内容创作者，我想在页面滚动、原页面状态变化或视口改变后让选框重新同步，以便操作辅助界面不与真实内容错位。
27. 作为内容创作者，我想让编辑模式中的普通点击只选择对象而不触发原链接、按钮或翻页逻辑，以便不会因编辑而误跳转或改变页面状态。
28. 作为内容创作者，我想让原页面的编辑快捷键与页面快捷键互不争夺，以便撤销、重做等操作具有可预测结果。
29. 作为内容创作者，我想在编辑模式中默认暂停 CSS 动画和过渡，以便运动中的对象可以稳定选中和调整。
30. 作为内容创作者，我想切换到预览模式恢复原页面动画，以便检查修改后的实际播放效果。
31. 作为内容创作者，我想双击文字对象后在真实渲染位置输入，以便直接看到文字与原页面样式、尺寸和排版的关系。
32. 作为内容创作者，我想在基础文字编辑中尽量保留原有的强调、代码和局部内联结构，以便改字不会无意清除已有格式。
33. 作为内容创作者，我想让从外部粘贴的内容按纯文本进入，以便避免把其他应用的复杂样式带进文档。
34. 作为内容创作者，我想在替换全部文字会清除内部格式时收到明确提示，以便在提交前理解影响。
35. 作为内容创作者，我想让文字变化立即按原 CSS 自然重排，以便看到真实的换行和布局结果。
36. 作为内容创作者，我想修改整个文字对象的常用字体属性，以便无需字符级富文本编辑器也能调整整体排版。
37. 作为内容创作者，我想修改文字颜色，以便让内容符合展示主题或强调需求。
38. 作为内容创作者，我想用本地图片替换选中的现有图片，以便更新产品图、示意图或背景素材。
39. 作为内容创作者，我想在替换前看到选中图片及其基础信息，以便确认不会改错对象。
40. 作为内容创作者，我想让替换后的图片立即出现在工作副本中，以便检查原尺寸规则下的真实显示效果。
41. 作为内容创作者，我想拖动选中的文字、图片或普通容器，以便通过视觉位移微调它在当前参考视口中的位置。
42. 作为内容创作者，我想在拖动过程中连续看到结果，以便不必松手后再猜测最终位置。
43. 作为内容创作者，我想让拖动只改变对象的视觉位置、不改变它在原文档流、Flex 或 Grid 中的占位，以便一次局部调整不会自动重排相邻内容。
44. 作为内容创作者，我想在视觉位移可能造成重叠或留下原占位时仍得到可预测结果，以便由我决定是否接受视觉取舍。
45. 作为内容创作者，我想拖动选框角部手柄等比视觉缩放对象，以便像在演示文稿工具中一样改变显示尺寸。
46. 作为内容创作者，我想在缩放过程中连续看到结果，以便根据周边内容即时调整。
47. 作为内容创作者，我想让视觉缩放不改变对象在原布局中的宽高与占位，以便避免无意触发响应式重排。
48. 作为内容创作者，我想让视觉位移和视觉缩放与对象原有变换共同生效，以便修改不会覆盖原页面已有的变换或动画定义。
49. 作为内容创作者，我想修改选中对象的背景色，以便调整普通容器或文字区块的视觉层次。
50. 作为内容创作者，我想修改选中对象的边框颜色、样式与宽度，以便突出或弱化对象边界。
51. 作为内容创作者，我想修改选中对象的圆角，以便让卡片、按钮式内容或图片外观符合需要。

## Implementation Decisions

- 首版产品是无需登录的本地优先 Web 编辑器。产品服务器仅分发编辑器前端静态资源；用户上传的 HTML、替换图片、修改层、编辑历史、本地项目状态和导出过程都留在浏览器中。
- MVP 只接受一个本地 `.html` 文件，不接受 ZIP、资源目录、多文件网站或 React、Vue 等源码工程。文件中的内嵌资源直接使用，外部 URL 按原地址加载，未一并提供的本地相对资源标记为缺失。
- 用户上传内容按受信任输入处理。承载工作副本的 iframe 用来隔离编辑器界面布局并提供独立文档环境，不被视为不可信代码的安全边界；原 HTML 的脚本、外部资源、网络请求和交互允许运行。进入导入流程前必须向用户说明此边界。
- 导入保真优先于完全可编辑。原 HTML、CSS 和 JavaScript 继续作为页面运行基础；能力检测确认可可靠处理的内容成为可编辑对象，其余内容作为锁定内容保留原效果。产品不把 HTML 转换为固定幻灯片或统一组件模型。
- 原始上传 HTML 在项目生命周期内保持不可变。当前工作副本由原始 HTML 与修改层组合而成，所有用户修改只记录在修改层和编辑历史中；导出始终基于原始 HTML 的副本生成新文件。
- 工作副本中的可编辑对象获得稳定、唯一的编辑标识。修改层通过编辑标识关联对象，而不是依赖 CSS 选择器、DOM 路径或文字内容；导出后的 HTML 保留这些标识。
- 首版可直接编辑的对象类型为文字对象、普通图片和普通容器。SVG、Canvas、视频、iframe、图表及复杂组件不开放内部编辑；若能够稳定确定外框，可作为整体对象选中，否则保持锁定。
- 编辑工作台采用演示文稿编辑器式布局：顶部承载文件、历史、模式、参考视口与导出操作；左侧承载可搜索 HTML 层级和锁定状态；中央承载实时工作副本与透明操作层；右侧承载当前对象属性；底部承载缩放、对象路径、资源和兼容性状态。长页面不显示幻灯片缩略图。
- 编辑使用可配置桌面参考视口，默认尺寸为 1440×900。原 HTML 的响应式规则继续运行，但修改层只保证在当前参考视口下符合预期；参考视口不改变文档形态，也不把长页面切分为固定页面。
- 选择从点击位置的最小可编辑对象开始，并允许通过再次选择、层级路径或层级树向上选择父容器。父容器被选择后可作为整体移动或缩放，但首版不把其内部结构转换为编辑组。
- 编辑模式由透明操作层优先接管对象选择、拖拽、缩放和编辑快捷键。普通点击不执行原页面的链接、按钮或点击处理；页面滚动保持可用。预览模式停用并隐藏操作层，恢复原页面的点击、键盘、滚动和动画。
- 编辑模式默认暂停 CSS 动画和过渡，以稳定对象位置与选框；切换到预览模式后恢复原定义。首版不修改动画定义，也不提供动画参数编辑。
- 双击文字对象进入真实渲染位置上的直接编辑。编辑器尽量保留已有内联标记，粘贴按纯文本处理，文字属性作用于整个文字对象；明确执行“替换全部文字”时可以清除内部格式，但必须在提交前提示。
- 文字变化由浏览器按照原 CSS 自然重排并即时显示。首版不引入独立文字排版引擎，也不承诺阻止文字变化影响周边布局。
- 首版文字属性覆盖常用的对象级字体设置，包括字体族、字号、字重、字形、行高、字间距、对齐和文字颜色；不提供字符区间级富文本格式。
- 图片编辑仅要求用本地图片替换现有普通图片，并沿用原对象的布局规则和基础外观。替换图片进入本地项目，导出时内嵌到 HTML 交付文件中。
- 拖动对象产生视觉位移，不改变对象在原文档流、Flex 或 Grid 中的占位，也不触发相邻内容自动补位。由此产生的重叠或空白属于该操作已知且可见的结果。
- 画面手柄缩放产生默认保持纵横比的视觉缩放，不改变对象的布局宽高和占位。首版不提供通过属性面板修改布局尺寸，也不要求自由拉伸或图片裁剪。
- 视觉位移和视觉缩放必须与对象已有变换组合，不能用一条新的 `transform` 直接覆盖原页面的变换或动画定义。
- 首版外观属性为文字颜色、背景色、边框颜色、边框样式、边框宽度和圆角。属性修改通过编辑标识生成局部样式覆盖，只作用于当前选中对象；不改写原始共享 CSS 规则，也不批量改变同类对象。
- 所有受支持的修改在操作过程中连续更新工作副本，并由浏览器真实渲染。选框、手柄、参考线、层级树和属性面板只属于编辑辅助界面，不进入预览结果或导出内容。
- 每个已提交的用户意图形成一个统一编辑历史步骤。文字、图片、位置、缩放和外观修改均支持撤销与重做；撤销和重做同步更新工作副本、选中状态及相关属性显示。
- 自动保存发生在每次已提交操作之后，保存原始 HTML、当前修改层和编辑历史。刷新或重新打开浏览器后可以恢复最近项目；保存失败或存储空间不足必须显式告知，不能继续显示虚假的已保存状态。
- 导出时，适合静态表达的文字和图片内容直接写入带编辑标识的对应对象；视觉修改集中写入编辑器专用 CSS 导出补丁。原始 CSS 与 JavaScript 主体尽量保持不变，首版不为复杂动态 DOM 注入通用冲突修复运行时。
- 导出产物是新的单文件 HTML 交付文件，不能覆盖用户最初上传的文件。它必须脱离编辑器运行；本地替换图片必须内嵌，原文件已有外部资源和外部脚本继续保留原链接。
- 首版正式支持最新版桌面 Chrome 和 Edge。Firefox、Safari 和移动浏览器不在兼容保证内，可显示兼容性提示；HTML 交付文件在其他浏览器中的运行能力仍由原文档实现决定。
- 产品内不提供 HTML、CSS 或 JavaScript 源码编辑入口。无法通过首版可视化能力处理的内容应锁定，而不是建立另一套绕过修改层、编辑历史和导出机制的修改路径。
- 首版发布门槛由最小编辑、预览与导出闭环定义。早期架构决策中已经确定但未列入该闭环的增强能力仍是后续方向，不应成为首版实现或验收的隐含要求。

## Testing Decisions

- 测试只验证用户可以观察到的外部行为，不锁定状态管理方式、组件划分、内部事件名称、修改层数据结构或具体 DOM 层级。只要用户流程、工作副本渲染、本地恢复和 HTML 交付文件满足本 spec，内部重构不应导致测试失败。
- 首要且默认唯一的测试 seam 是受支持桌面 Chromium 中的浏览器端端到端测试：从编辑工作台上传真实 HTML，执行用户操作，观察实时工作副本，刷新并恢复本地状态，下载 HTML 交付文件，再在不加载编辑器的独立页面环境中打开并验证结果。新增更低层 seam 只有在浏览器端无法稳定制造关键错误条件时才可采用。
- 导入、能力检测、选择、直接编辑、修改层应用、编辑历史、模式切换、本地保存和导出虽然是不同模块职责，但应优先通过同一个端到端 seam 共同测试，避免为内部模块分别建立易与实现耦合的测试接口。
- 现有测试先例是两份验收样例：一份包含翻页、主题切换、全屏与脚本交互的 HTML 展示文档，以及一份包含导航、滚动、响应式区块、外部图片和进入视口动画的 HTML 展示文档。两者都必须使用未经预处理的原始输入走完整闭环。
- 两份验收样例的共同基础场景包括：成功导入；原布局和主要可见内容保持；页面能够按原形态浏览；最小对象选择和父容器选择可用；锁定内容有明确状态；文字修改、图片替换、视觉移动、视觉缩放及首版外观调整即时呈现；撤销和重做恢复正确结果；预览模式隐藏编辑辅助界面并恢复原行为；刷新后恢复修改；导出文件独立打开后保留修改。
- 翻页验收样例必须额外验证：编辑模式点击可编辑对象不会误触发上一页、下一页、主题切换或全屏操作；预览模式中原翻页和主题行为恢复；编辑时动画冻结不会改写导出文件中的原动画定义；在不同页面状态下选框可以重新同步当前可见对象。
- 长滚动验收样例必须额外验证：滚轮和滚动条在编辑模式可用；页面不会被切割为幻灯片；导航与锚点在预览模式恢复；滚动到不同区块后可以选择和编辑对象；参考视口变化继续触发原响应式 CSS；视觉修改只在当前参考视口下做结果保证。
- 文字编辑测试应覆盖普通纯文字、含内联标记文字、纯文本粘贴、替换全部文字的警告、自然换行与周边布局变化，以及撤销后恢复原文字和内联结构。测试断言最终可见内容和必要语义，不对浏览器生成的中间编辑 DOM 做快照。
- 图片替换测试应覆盖本地图片即时显示、撤销与重做、本地恢复、导出后无需原本地图片文件即可显示，以及替换只作用于选中图片。
- 视觉操作测试应验证连续反馈、最终显示位置和尺寸、原布局占位未被改写、同类对象未被连带修改，以及原有变换仍然存在。测试以渲染边界和邻近内容的可观察结果为准，不断言内部 CSS 属性如何拆分。
- 外观属性测试应覆盖文字颜色、背景、边框和圆角的设置、撤销、重做、本地恢复和导出一致性；共享类名对象必须作为回归用例，确认局部样式覆盖不会影响未选中的同类对象。
- 编辑历史测试应以用户意图为粒度，覆盖各支持操作、连续多步撤销、连续多步重做、撤销后产生新操作时的正确历史行为，以及回到原始导入状态。测试不依赖内部 action 或 reducer 名称。
- 模式测试应验证编辑辅助界面不会进入预览或导出；编辑模式不触发原页面点击和键盘交互；预览模式恢复点击、键盘、滚动和动画；往返切换不会丢失修改或制造额外历史步骤。
- 本地保存测试应覆盖每次提交后的持久化、刷新恢复、浏览器重新打开后的最近项目恢复、原始上传内容保持不变，以及存储写入失败或容量不足时显示可操作错误。测试环境应隔离每个用例的浏览器存储，避免跨用例污染。
- 导出测试必须把下载文件视为最终产品而不是实现快照。验证项包括：文件是单个 HTML；不依赖编辑器运行；所有首版修改与导出前工作副本一致；本地替换图片已内嵌；原有脚本和交互仍可运行；编辑辅助界面不存在；稳定编辑标识保留；原始上传文件未被覆盖。
- 导入错误测试应覆盖非 HTML 文件、无法解析或无法载入的输入、缺失相对资源和不受支持浏览器提示。受信任输入提示以及“产品本地处理不代表原页面不会联网”的说明也应作为可见产品行为验收。
- 视觉保真采用针对关键页面状态的截图或区域级视觉比较，并辅以实际交互断言。允许浏览器字体渲染等可解释的小幅差异，但不能接受由编辑器引入的结构重排、动画删除、交互失效或未编辑对象样式变化；具体容差在测试基线建立时固定记录。
- 首版不把任意第三方 HTML 的兼容性数量当作自动化覆盖目标。两个验收样例完整通过才构成发布必要条件，但不代表产品宣称支持所有 AI 生成 HTML。

## Out of Scope

- 在产品内调用 AI 生成或修改 HTML，以及浏览器端自带模型密钥。
- ZIP、资源文件夹、多文件网站、网页工程、React/Vue 源码工程和任意目录导入。
- 对不受信任或恶意 HTML 的安全沙箱、脚本审查、受控通信桥接或无风险承诺。
- 把任意 HTML 转换为固定 16:9 幻灯片、统一页面模型或产品专有组件树。
- 对所有 AI 生成 HTML 的完整可编辑承诺、像素级保真承诺或复杂动态 DOM 的通用兼容保证。
- 新增文字、图片、矩形、形状、按钮、表格、图表或复杂组件。
- 复制、隐藏或删除现有对象作为首版发布门槛。
- 多选、框选、对齐、平均分布、编辑组和跨对象批量修改。
- 旋转、自由拉伸、图片适应/填充/裁剪、阴影、叠放层级和布局宽高编辑。
- 字符区间级富文本格式、任意 HTML 粘贴或完整所见即所得富文本编辑器。
- 动画预设、动画时间轴、关键帧、运动路径或任意 JavaScript 动画编辑。
- 复杂 JavaScript 动态对象的冻结编辑、逐属性运行时冲突检测和动态重建对象的自动身份恢复。
- 编辑模式中的连续交互工具或辅助键单次执行原页面交互；首版通过预览模式验证原交互。
- 可移植项目文件的导入与导出、跨设备同步、云端项目、账号、团队、评论和权限。
- 自动下载并内嵌原文档已有的外部图片、字体和样式，以及完整资源报告。首版仅保证用户本地替换的图片进入 HTML 交付文件。
- 完全离线承诺。原 HTML 已有的外部资源、外部脚本和主动网络请求可继续访问第三方服务。
- 在线分享链接、托管发布、PPTX、PDF 或文件夹式交付物。
- HTML、CSS 或 JavaScript 源码编辑模式。
- 手机或平板断点的独立编辑、跨断点修改规则，以及所有屏幕尺寸的自动适配保证。
- Firefox、Safari、移动浏览器和旧版 Chrome/Edge 的正式编辑兼容保证。

## Further Notes

- 本 spec 使用项目领域词汇，并以仍然有效的架构决策为约束。已经废弃的“固定幻灯片混合布局”和“浏览器端自带模型密钥”不进入实现范围。
- 当早期决策描述了更完整的长期能力、而首版最小闭环明确缩小了发布范围时，以最小闭环为首版发布门槛；更完整能力保留为后续 spec，不应被静默实现成首版依赖。
- 两份验收样例是首版支持声明的证据边界，不是产品演示素材，也不是“支持所有 HTML”的替代说法。
- 浏览器本地数据可能被用户、浏览器或系统清除。首版应清楚提示这一限制；可移植项目文件属于后续能力，因此 HTML 交付文件仍是当前唯一由用户主动带走的成果文件。
- 需求材料尚未规定上传文件大小上限、浏览器本地项目数量上限、自动保存保留策略和导出文件命名规则。实现不应引入无法解释的任意产品限制；若浏览器能力迫使设置限制，应以可见、可恢复的错误呈现，并在实现决策中记录具体值。
